# ADR-003: На немецком VPS остаётся Qwen2.5 0.5B

- **Статус:** заменено ADR-004
- **Дата:** 2026-10-25
- **Area:** integration
- **Авторы:** команда Servys
- **Связь:** дополняет ADR-002. Роль модели не меняется: только извлечение фактов из короткого фрагмента в JSON. Сроки обслуживания по-прежнему считает детерминированный Go.

## Контекст

Модель должна быть бесплатной и помещаться на немецкий сервер. 2026-10-25 на `5.252.225.191` (netcup, тот же хост, где у trainys шлюз Telegram) измерено:

- 2 vCPU
- 1,9 ГиБ RAM, свободно около 1,5 ГиБ
- 4 ГиБ swap
- на диске свободно около 45 ГБ
- на хосте уже работает шлюз Telegram

`qwen2.5:1.5b` из ADR-002 — файл около 1 ГБ и рабочий процесс 1,2–1,6 ГБ. Рядом со шлюзом она уходит в swap и может вытеснить шлюз. Облачный API с ключом и оплатой не подходит.

## Решение

Рабочая модель на этом сервере — **Ollama `qwen2.5:0.5b`**.

- лицензия Apache 2.0, локальный запуск, без аккаунта и без оплаты;
- файл около 400 МБ, рабочий процесс около 0,6 ГБ;
- контекст не больше 2048 токенов, модель выгружается через 30 секунд простоя, чтобы не сидеть в памяти рядом со шлюзом.

Переменная `OLLAMA_MODEL` по-прежнему подменяет модель. `qwen2.5:1.5b` допустима только на машине, где под Ollama есть отдельные 2 ГБ, и на этот немецкий VPS её не ставить.

На живой хост trainys модель этим изменением не устанавливается: там уже обслуживается чужой шлюз.

Модель не выбирает, что обслужить. Она читает короткий фрагмент документа и возвращает факты. Варианты работ и статусы «скоро / пора / просрочено» считает движок по правилам и по истории, которую внёс владелец.
