# ADR-004: Основная модель проекта — Qwen2.5 7B

- **Статус:** заменено ADR-005
- **Дата:** 2026-10-28
- **Area:** integration
- **Авторы:** команда Servys
- **Связь со спекой:** §4 в `docs/superpowers/specs/2026-07-11-servys-mvp-design.md`
- **Связь:** заменяет размер модели из ADR-003. Роль модели прежняя: выбрать запрос и страницу, прочитать фрагмент без таблицы и вернуть JSON. Сроки считает Go. Ключ облачной модели в код не кладётся.

## Контекст

Локальный разбор Kia K3 сделала `qwen2.5:7b`: она сформулировала запрос и открыла регламент. `qwen2.5:0.5b` и `qwen2.5:1.5b` на том же шаге часто ломают JSON. Файл `qwen2.5:7b` — 4,7 ГБ, рабочий набор около 8 ГБ при контексте 4096.

Измеренный хост `5.252.225.191` (ADR-003): 2 vCPU, 1,9 ГиБ RAM, 4 ГиБ swap, рядом шлюз Telegram. Туда 7B в память не помещается. Swap шлюз не заменяет.

Текст на снимке сервисной книжки читает PaddleOCR (`backend/ocr`), не эта модель. `qwen2.5:7b` текстовая.

## Решение

Основная модель проекта — **Ollama `qwen2.5:7b`**, и локально, и на сервере.

- Пустой `OLLAMA_MODEL` в коде означает `qwen2.5:7b`.
- Контекст для чтения страниц — 4096, выгрузка через `OLLAMA_KEEP_ALIVE` 30 с.
- Под Ollama нужно около 8 ГБ. На хост с 1,9 ГиБ эту модель не ставить, пока машину не увеличат. `qwen2.5:0.5b` остаётся только ручным откатом на таком хосте.

## Рассмотренные альтернативы

- **`qwen2.5:0.5b`** — помещается на измеренный VPS, не выбирает страницу и не держит JSON.
- **`qwen3.5:9b`** — сильнее на русском тексте, в лимит 8 ГБ входит впритык и в проекте не проверена.
- **Модель с картинками** — снимок уже читает PaddleOCR. Вторая модель на тот же файл не нужна.

## Последствия

- ✅ Одна модель и для выбора страницы, и для чтения отзыва.
- ⚠️ Сервер с 1,9 ГиБ эту модель не запустит. Сначала память хоста, потом `ollama pull qwen2.5:7b`.
- 🔗 HTTP-контракт не меняется. Снимок по-прежнему идёт в OCR, не в Ollama.
